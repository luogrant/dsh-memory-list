# 记忆树 · 记忆空间 —— 项目介绍

> 上游仓库：<https://gitee.com/vampirexx/memory-list>
> 本仓库（插件化改造版）：<https://github.com/luogrant/dsh-memory-list>

## 一、这是什么

一套**自己跑的记忆系统**，只由三样东西构成：

- 一份 JSON 文件（`data/识海.json`）= 整个记忆库；
- 一个 Node 进程（`app.mjs`）= 全部后端服务；
- 四个页面（列表 / 汲取 / 星图 / 人设 / 五轨）= 全部界面。

没有数据库、没有 Web 框架、没有前端构建、没有 npm 依赖。`node app.mjs` 起来就是一个能用的记忆空间。

它要回答的问题很具体：**大模型的上下文是有寿命的，而人希望它记住的东西是无期限的。** 常规做法是"把历史全塞进 prompt"或"向量检索"，两种都会在长周期里失控——前者爆窗口，后者召回一堆语义相近但毫无因果关系的碎片。这个项目的答案不是更好的检索，而是**给记忆建一个会新陈代谢的结构**：树决定放哪里，层级决定活多久，四个模型算法负责搬进去和搬出来。

## 二、核心骨架：一棵有层级的树

记忆不按"类型"分类，按**认知深度**分层。层级规则写在 `data/识海.json` 的 `tree.rules.levels`，是硬校验，不是建议：

| 层 | 名称 | 写入权限 | 生命周期 |
|---|---|---|---|
| T0 | 记忆构成 | 只读 | 永久 |
| T1 | 因素链条 | 只读（审核后写入） | 永久 |
| T2 | 衍生链条 | 读写 | 永久 |
| T3 | 衍生链条 | 读写 | 60 天 |
| T4 | 因果链条 | 读写 | 45 天 |
| Q5 | 短期记忆 | 读写 | 30 天 |

配套的三条流水层（同样在树里，作为 T0 根节点存在）：

| 节点 | 作用 | 生命周期 |
|---|---|---|
| S 记忆汲取 | 新来的原始事实 | 5 天 |
| M 瞬时记忆 | 整理后保留的有效事实 | 10 天 |
| W 垃圾记忆 | 判废内容，留档观察 | 30 天 |

**层级顺序是强制的**：T0 → T1 → T2/T3 → T4。`addChildNode()` 会直接拦掉越级挂载（T1 只能挂 T0 下、T2/T3 只能挂 T1 下、T4 只能挂 T2/T3 下）。T2 与 T3 是**并列的两条路**，区别只在时限（一条永久、一条 60 天），各自往下接 T4。节点上还有记忆或子节点时删不掉，必须先清空。

出厂骨架的 T0 有 7 个根：`执行规则`、`S 记忆汲取`、`M 瞬时记忆`、`W 垃圾记忆`、`主体 - 意识本体`、`成长日记`、`项目记录`。其中 `主体` 下挂 8 个分支（人设人格 / 重要经历 / 能力优缺 / 喜厌嗜好 / 本我 / 自我 / 超我 / 碎片），每个分支再往下是「清单 → 成因」这种 T1→T2/T3→T4 的三段结构。骨架只是形状，**仓库里不带任何记忆条目**，打开就是空库，可以自己长。

时限是怎么生效的：`rules.levels` 里每层一个 `life`（"永久" 或天数），条目在**写入时**按目标层算出 `exp` 到期日；读取时过期的直接被过滤掉。所以"忘记"不是靠手动删除，是到期自动消失。

## 三、五条轨：给明确事项准备的抽屉

树是给机器自动整理用的，人有时需要**立刻记一条、且不希望它被算法揉碎**。这就是五轨：

| 轨 | 放什么 |
|---|---|
| `memory` | 全局记忆 |
| `user` | 用户档案 |
| `project` | 项目记忆 |
| `key` | 关键记忆（晋升时也会在这里留痕） |
| `daily` | 今日流水 |

关键设计：**五轨不跟每轮对话走**。对话内容由自动汲取和自动整理处理、写进树节点；五轨只在"明确事项"（项目进展、关键决定、用户档案）时手动写。这条界线避免了两套记忆打架。

## 四、四个算法

都在 `app.mjs`，共同点是"一次模型调用做一次判断，代码可读、参数可改"。默认模型 `deepseek-chat`，配置在 `llm.json`（`baseUrl` / `model` / `maxTokens:3000` / `temperature:0.2` / `timeoutMs:120000`）。

### 1. 汲取 sScan()：把对话变成记忆

```
读会话日志 → 只取完整轮次（user/assistant 成对）→ 丢噪音
→ 一次模型调用判断"这轮里有没有值得记的事实"
→ 得到 [{text, path}]，path 必须从树上已有节点里选，不许自造节点
→ 写进 S 节点，按层给到期日
```

系统提示的第一句就是它的定位：*「你是记忆整理器。从一段 user/assistant 对话里抽取值得长期记住的内容：明确说出的结论、决定、规则、偏好、踩坑与修法、被证伪的判断。」* 输入正文截断到 12000 字符。

自动模式默认 **2 小时一轮**，只扫"没扫过的最近 3 个会话"，用 `auto.doneSids` 记账，绝不把历史全翻一遍——这是它敢常驻的原因。

### 2. 整理 sTidy()：给新记忆判死刑

把 S 里的条目一次性交给模型（提示词自称"海马体"），逐条分类：

- `keep` → 有效，进 **M 瞬时记忆**
- `trash` → 垃圾，进 **W 垃圾记忆**
- `merged` → 同一件事说了三遍以上，合并成一条，进 M

写完删源条目。自动模式默认 **24 小时一轮**。

### 3. 晋升 sPromote()：重复即重要

不调模型的统计步骤：统计 M 里同一重点词的累计出现次数，**≥3 次**的合并成一条写进 **Q5（主体 › 碎片）**，同时在 `key` 轨留一条记录，删掉 M 里的源条目。

### 4. 自主归位 sPromoteQ5()：让它自己决定记什么

最"人格化"的一步。提示词第一句是：*「你就是这条鱼本人，现在在做「自主意识」这一步：Q5 短期记忆里的东西，由你自己决定哪些该记住、哪些不该记住。」* 模型返回：

```json
{ "remember": [{ "from": "q5-id", "to": "node-path", "text": "...", "why": "..." }],
  "forget":   [{ "from": "q5-id", "why": "..." }] }
```

落点只允许是树上 `level 2~4` 的节点，不许越级、不许造节点。记住的写目标层并按该层 life 给到期日，忘掉的直接删。

四个算法连起来就是一条完整的代谢链：

```
对话日志 ──汲取──▶ S ──整理──▶ M ──晋升──▶ Q5 ──自主归位──▶ T2/T3/T4（长期）
                    └──▶ W（垃圾，30 天后自灭）
```

## 五、界面

`index.html` 五个页签：

- **列表** —— 树形浏览、搜索、条目的增删改
- **汲取** —— 选会话、跑汲取、看结果（`apply:false` 可以先只看不写）
- **星图** —— 打开 `pages/星轨.html`：canvas 自绘的 3D 星轨，节点是星、层级是距离，带 HUD / 图例 / 树侧栏 / 巡游按钮，可点星编辑
- **人设** —— 人设快照的增改删（schema 参考 `dsh-agent-persona`）
- **五轨** —— 五条轨的读写界面

页面每 4 秒轮询 `GET /api/rev`（`rev` 是数据文件 sha1 前 10 位），库一变界面就自己跟上，不用手动刷新。

## 六、数据长什么样

```
data/识海.json
├─ version / built_at
├─ tree     { rules, tree[] }                  树的形状与层级规则
├─ personas []                                 人设快照
├─ tracks   { memory, user, project, key, daily }
├─ store    { "2026-01-01": [ 条目, ... ] }    记忆条目，按天分桶
├─ state    {}                                 运行时状态
└─ auto     { intake, tidy, intakeEveryHours, tidyEveryHours, lastIntakeAt, lastTidyAt, doneSids }
```

条目：`{ t, lv, path, text, exp, hit, ws, src }` ——
时间 / 层级 / 挂载路径 / 正文 / 到期日 / 命中次数 / 工作区 / 来源。

树节点：`{ id, name, level, level_label, path, perm, limit, life, children }`。

写入策略很保守：`saveDb()` 先写 tmp 再 rename，并且**每天留一份快照**到 `state/backup/`，只保留最近 30 份。所以改坏了总能退回昨天。

## 七、跑起来

```bash
export DEEPSEEK_API_KEY=sk-...   # 汲取/整理/晋升要调模型；不填也能看界面
node app.mjs
# → http://127.0.0.1:8080/
```

| 变量 | 作用 | 默认 |
|---|---|---|
| `SHIRAM_PORT` | 端口 | `8080` |
| `SHIRAM_DATA` | 数据文件位置 | `./data/识海.json` |
| `SHIRAM_BACKUP` | 备份目录 | `./state/backup` |
| `SHIRAM_LLM_CONFIG` | 模型配置位置 | `./llm.json` |
| `DSH_HOME` | 会话日志根目录 | `~/.dsh` |
| `SHIRAM_SESSIONS` | 直接指定会话日志目录 | — |
| `DEEPSEEK_API_KEY` | 模型 Key；不给就读 `$DSH_HOME/.credentials.yaml` | — |

服务只监听 `127.0.0.1`，`localOnly()` 拦掉非本机请求——它天生是个本地工具，不是能挂公网的服务。

## 八、接口一览

| 接口 | 作用 |
|---|---|
| `GET /api/tree` | 整棵树（`?q=` 过滤） |
| `GET /api/rev` | 版本号，页面 4 秒轮询 |
| `GET /api/status` | 库状态（条数、天数、五轨计数、人设数） |
| `GET/POST /api/tracks/<轨>` | 读 / 写五轨 |
| `POST /api/memory/add·update·delete` | 条目增删改 |
| `POST /api/tree/add-node·rename·delete-node` | 树操作 |
| `GET /api/sessions` | 可汲取的会话列表 |
| `POST /api/intake/scan` | 汲取（`apply:false` 只预览） |
| `POST /api/intake/tidy` | 整理 |
| `POST /api/intake/promote` | M → Q5 晋升 |
| `POST /api/intake/promote-q5` | Q5 → T2/T3/T4 归位 |
| `GET/POST /api/auto` | 自动汲取 / 自动整理开关 |
| `GET /api/personas` | 人设 |

## 九、设计取舍（值得单独说的三点）

1. **JSON 当库，不引数据库。** 好处是整个库可以 `git diff`、可以直接备份、可以在编辑器里手改；代价是并发写入靠"写 tmp 再 rename"兜底，适合单人单机。
2. **层级是硬约束，不是提示词。** 模型返回的 `path` 会被校验必须来自树上已有节点，越级挂载直接报错。这是把"别乱造节点"从"请模型自觉"变成"代码不允许"。
3. **只读层 T0/T1。** 最稳定的认知（记忆构成、因素链条）不允许算法直接改写，只能人工审核后写入；算法能动的只有 T2/T3/T4 和 Q5。这防止自学习把地基揉烂。

## 十、本仓库的插件化改造

上游是"独立 Node 服务 + 8080 端口"的形态。本仓库把它改造成 **DeepSeek Harness 原生插件**，功能与数据格式完全一致，只是接入方式变了：

| 方面 | 上游 | 本仓库 |
|---|---|---|
| 运行方式 | `node app.mjs`，自己监听 8080 | 挂进 DSH 的 webServer，走 `/dsh-memory-list/` 前缀 |
| 界面入口 | 浏览器开 `localhost:8080` | DSH 侧栏「识海」页签，主区内嵌 iframe |
| 数据位置 | `./data/识海.json` | `$DSH_HOME/memory-list/`，可用 `SHIRAM_HOME` 改 |
| 启动时机 | 手动 | 宿主加载即 `apply()`，自动任务随插件起停 |
| 鉴权 | `localOnly()` 只认 127.x | 叠加 DSH 的 `requestRejection` |
| 独立运行 | 是 | 仍然保留：直接 `node app.mjs` 照样跑 |

改造的技术要点：数据文件懒加载（首次请求才建库，缺文件自动从骨架初始化），HTTP handler 抽成 `async function 处理请求(req,res)` 供宿主调用，自动任务包成 `起自动任务()` 返回清理函数交给 `ctx.effect` 释放，前端所有 `/api/...` 改成相对路径（这样在 `/` 和 `/dsh-memory-list/` 下都能用）。
